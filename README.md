# ИТОГ — офлайн-приложение для подготовки к итоговому сочинению

Исходный проект первой версии Android-приложения на Kivy. Внутри — тренажёр тем, мастер сочинения, счётчик слов, локальная библиотека литературных произведений, сохранение черновиков, простая структурная проверка, статистика и локальный ИИ-наставник.

## Важная особенность: один APK

В APK встраиваются:

- Python/Kivy-приложение;
- нативный движок `llama.cpp`, собранный под `arm64-v8a`;
- GGUF-файл `Qwen3-4B-Q4_K_M.gguf`.

После установки не нужны Termux, отдельный сервер, API-ключ или интернет. Модель не загружается приложением при первом запуске: она уже должна находиться в APK.

**Размер:** модель занимает около 2,5 ГБ. Итоговый APK будет очень большим и потребует нескольких гигабайт свободного места при сборке и установке. Для Google Play такой способ распространения не подходит как обычная публикация: там действуют отдельные ограничения размера загрузки. Это сборка для прямой установки/тестирования, не готовая публикация в магазине.

## Требования к телефону

Целевое устройство — Samsung Galaxy S24 Ultra, ARM64, 12 ГБ оперативной памяти. Начальные параметры: Qwen3-4B Q4_K_M, контекст 8192 токена, 6 CPU-потоков. Текущая нативная сборка использует CPU, без Vulkan/GPU offload. Для первой версии это самый предсказуемый путь сборки; ускорение через GPU можно добавить отдельно после проверки стабильности на конкретной прошивке. Скорость зависит от прошивки, температуры, фоновых приложений и свободной памяти. При перегреве Android может снижать частоту процессора.

## Подготовка модели

Модель Qwen3-4B-GGUF опубликована под лицензией Apache-2.0; модель распространяется отдельно от кода приложения. В проект добавлен скрипт загрузки официального GGUF из организации Qwen:

```bash
bash scripts/download_model.sh
```

После загрузки файл должен находиться здесь:

```text
assets/models/Qwen3-4B-Q4_K_M.gguf
```

## Сборка движка под Android

Нужны Linux/Ubuntu или WSL2, CMake 3.22+, Android SDK и Android NDK. В Android SDK Manager установи NDK. Затем:

```bash
export ANDROID_SDK_ROOT="$HOME/Android/Sdk"
export ANDROID_NDK_HOME="$(find "$ANDROID_SDK_ROOT/ndk" -mindepth 1 -maxdepth 1 -type d | sort -V | tail -n 1)"
bash scripts/build_native_android.sh
```

Скрипт скачивает исходный `llama.cpp`, собирает CPU-движок для `arm64-v8a` и помещает библиотеку в `native/libs/arm64-v8a/`.

## Сборка APK

Установи Buildozer в Linux/WSL2 и Android build dependencies, затем:

```bash
pip install buildozer
bash scripts/build_apk.sh
```

Готовый APK Buildozer создаёт в каталоге `bin/`.

## Как устроен ИИ-наставник

ИИ работает локально через `ctypes`-обёртку над `libessay_llama.so`. Он умеет:

- разбирать формулировку темы и выделять главный вопрос;
- предлагать варианты тезиса и план, объясняя риски ухода от темы;
- подбирать произведения из встроенной библиотеки;
- проверять план и аргументацию;
- разбирать сочинение по К1–К5;
- объяснять правила и отвечать на вопросы.

Локальная библиотека передаётся модели как справочный контекст (поиск по темам, произведениям, героям и эпизодам). В системной инструкции запрещено выдумывать цитаты и детали; при сомнении модель должна просить сверить их с произведением. Однако локальная языковая модель может ошибаться — её разбор является учебной рекомендацией, не официальной оценкой ФИПИ.

## Текущие ограничения первой версии

- Встроенные темы — учебные тренировочные формулировки по трём разделам ФИПИ, а не полный закрытый банк тем.
- Проверка орфографии пока не заменяет полноценный корректор; критерий К5 оценивается ИИ ориентировочно.
- Импорт рукописных фотографий/OCR, синхронизация между устройствами, аудиорежим и полноценный календарь подготовки не включены.
- Нативная библиотека и модель ещё должны быть собраны/вложены в APK. Этот архив — проект исходников и сценариев сборки, не готовый и не проверенный на устройстве APK. Нативная сборка зависит от актуального API `llama.cpp` и может потребовать корректировки при изменении upstream-ветки `master`.

## Сборка через GitHub Actions с телефона

В репозитории есть workflow `.github/workflows/build-apk.yml`. Загрузи исходники проекта в свой GitHub-репозиторий, открой вкладку **Actions**, выбери **Build one-file Android APK** и нажми **Run workflow**. GitHub runner скачает около 2,5 ГБ весов, соберёт нативный движок и APK. Затем скачай артефакт `itog-android-apk` из завершённого запуска Actions. На сборку расходуется много дискового пространства и времени; workflow может потребовать настройки, если Buildozer или Android SDK изменят совместимость.
